# PRODUCTION-RELEASE-MANIFEST-V1 — T-0043 host boundary

This format specifies canonical signed release metadata for LUF-0008b #37 and future #41 composition. It is implemented by [ProductionReleaseManifest](../src/LimitedUnderground.FirmwareLoader/ProductionReleaseManifest.cs) and tested by [ProductionReleaseManifestTests](../tests/LimitedUnderground.FirmwareLoader.Tests/ProductionReleaseManifestTests.cs). No production artifact, key, SPKI enrollment, trust-catalog entry, target activation or accepted release exists. A parser result is metadata, never operational authority. Production remains inspection-only. Host validation is not physical acceptance.

## Canonical bytes and schema

Exactly one UTF-8 JSON object, no BOM, whitespace or trailing newline, maximum 16384 bytes. Exactly the following properties, each once, in this order. Unknown, missing, duplicate and reordered fields refuse. Canonical strings/numbers are emitted by the bounded `Utf8JsonWriter` serializer; parsing must reserialize to identical bytes (including escapes). Numeric fields are unsigned base-ten integers without exponent/fraction/leading zero; times are UTC Unix milliseconds, bounded to signed64. Strings are ASCII printable, at most256 characters. Hex digests are exactly64 uppercase hex characters. No optional fields or extension bag.

## Signature and persisted D4 state

Detached signature is exactly384 bytes: existing RSA-PSS-3072/SHA256 verification over the entire canonical object, using a complete public SPKI (no trailing bytes). `HostReleaseAdmission` shares its existing bounds, immutable snapshots, target/layout/recovery binding, policy/key/generation checks, SHA256, address checks and RSA verification for the new payload. The legacy fixture entry point still signs/verifies its original canonical bytes. The existing `ValidUntil` comparisons are unchanged; production expiry must equal the current policy deadline.

Admission additionally requires an explicit, existing persisted state object. Its exclusive file transaction reads both highest accepted time and policy revision; now below the prior time or a lower revision refuses. A valid attempt advances both floors, flushes durably, and only then returns an admitted host result. Missing, corrupt, locked, inaccessible or unwritable state refuses; it is never initialized by verification. Bad signatures cannot advance state. A crash leaving a partial record causes refusal on reopening. An isolated test-only initializer supplies fixture genesis; it is not production enrollment or a protected-store implementation. No machine root is selected, enrolled or accessed.

D-011 expressly selects a host-clock high-water rule instead of per-session signed time. This detects rollback below stored history; it does not authenticate wall time, detect every frozen clock, or remove state-loss/tampering risk. Unknown/negative time and expiry refuse; persistence custody/enrollment remains #40. Invalid or untrusted future policy cannot become trusted merely by supplying a time. Sole-root compromise recovery remains an owner decision with no independent authority appointed.

## Authority and validation limits

The new typed result retains the complete manifest plus the existing admitted host release. It is opt-in and is not registered with production factories, UI or a device adapter. D5 current-state references and raw/padded byte identities are checked before admission. Production signature input now includes all source/build and contract references; tests specifically reject changing new metadata while retaining an old signature. Policy revision changes require a new canonical signature; no compatibility promise is made for an unsigned future release.

The task's maintained full Loader host gate and warnings-as-errors Release builds are required before describing this changed source as validated. Fourteen new registered groups cover canonical/field/refusal, signature, representation, current-state, expiry and persisted clock/policy cases. Actual results are recorded in the T-0043 report. Existing host tests are not production, physical or release acceptance. Public-key creation/activation, real signatures, transport, device and recovery operations remain outside this increment.
